# 单词记忆核心重构升级实施状态

日期：2026-09-11。范围：`vocab_flash_test` 阶段 0–6 实现与验证。

本次升级把应用的核心写入从“完成整轮后批量更新”改成“每次回忆提交即产生事实事件，再由状态投影驱动下一次复习”。保留现有 Flutter、Riverpod、Hive、四选一闪测和自定义 SRS，同时完成 SQLite 事务适配、稳定词条边界、FSRS 影子调度、能力题型扩展、用户暂不学习和凭据安全存储。

## 已交付

### 记忆领域

- `RecallEvidence`、`RecallEvaluator` 区分客观答题、自评回忆、提示/揭示后的辅助回忆和长期证据。
- `MemoryScheduler` 是新的调度入口，当前包装带版本边界的旧 `SrsAlgorithm`；页面不再直接决定长期状态。
- `MemoryState`、`LearningSkill`、`LearningItem`、`Lexeme`、`Sense` 和 `LegacyLexiconMapper` 建立了词条、义项、能力与记忆状态的边界。
- `Word.stableId` 和 `primarySenseId` 为旧数值 ID 提供稳定映射，不把旧识别记录复制成英文产出或拼写掌握。

### 可靠学习记录

- `ReviewEvent` 使用 session＋attempt 的稳定幂等键。
- Hive 仓储按 `pending → card state → committed` 顺序写入，并在启动时恢复 pending 事件。
- `CardState.revision` 用于乐观并发检查；重复提交不会重复推进 SRS。
- 手动标记“已认识”使用独立来源 flag，不伪造跨日独立回忆；下一次真实回忆会清除该 flag。
- 事件保存 `evaluationSource`、`taskType`、skill、rating、是否到期、是否揭示答案、是否使用提示、是否独立回忆和活跃时长等证据字段。
- `ExposureEvent` 独立记录词条接触，按稳定 ID 去重并参与每日新词统计；导入、导出、清空和恢复均覆盖新事件盒。
- 统计和每日历史优先读取已提交事件；中途结束的会话也能显示已提交回忆，旧库没有事件时继续读取旧轮次。

### 今日计划与学习入口

- `StudyPlanner` 以到期、重学、疑难、新词和时间预算排序，计划预览不扣额度。
- `StudyPlanService` 读取卡片与接触事实，首页展示今日项目数、新词数和预计时间。
- `StudyCandidate`/`PlannedItem` 带有 `LearningItem`、skill、taskType 和内容版本；识别和英文产出按能力独立计划，不会因同一 `wordId` 被去重合并。
- 用户可对稳定词条设置 `suspended` 偏好；计划器排除暂不学习的词条，疑难词页提供暂停与恢复入口。
- 传统测试入口接收计划产生的词条顺序；主动回忆入口提供“隐藏答案 → 揭示 → 自评”闭环。
- 新词额度在有效提交后消费，重复 attempt、恢复和同日重复接触不会重复扣减。
- 计划器以持久化 `ExposureEvent` 重新核对当日新词数；即使回忆事务提交后 UI 偏好写入前崩溃，也不会重新开放当天的新词额度。显式的空计划不会回退到全词库选词。

### 可恢复会话

- `SessionCheckpoint` 以版本化 JSON 保存主队列、延迟队列、重试次数、当前题选项、倒计时、答题记录和配置快照。
- 后台、退出和生命周期切换会保存检查点；恢复使用检查点配置，不被当前设置覆盖。
- 当前题与延迟队列恢复时会从主队列剔除，避免同一词条重复入队。

### 数据边界与迁移

- 移动端和 macOS 默认装配 `SqliteProgressRepository`；SQLite schema 建立 `lexemes`、`senses`、`learning_items`、`learning_item_states`、`review_events`、`exposure_events` 和迁移报告表。
- SQLite schema 已升级到 v2，加入 `word_preferences`，并用 `meta.schemaVersion` 记录实际 schema。
- `commitRecall` 将事件、识别状态、能力状态和首次接触记录放进同一个 SQLite 事务；提交按事件 ID 和 revision 幂等，启动时会重放 pending 事件。
- `LegacyProgressMigrator` 对旧 Hive 快照去除易变导出时间后计算 SHA-256，先写带校验和的本地备份，再导入空 SQLite；失败不会切换写入端，旧库保持不变。
- SQLite 迁移前把用户偏好也视为已有用户数据，避免目标库只有“暂不学习”记录时被旧快照覆盖。
- 迁移器依赖 `LegacyProgressSource`/`MigrationTarget` 端口，可对导入中断、失败记录和同 checksum 重试做故障注入；失败状态不会被误写成完成。
- 旧数值 `wordId` 映射到稳定 `legacy:<id>` Lexeme；历史识别状态不复制为英文产出、听力或拼写掌握。重置一个词时会同时清除它的能力级状态。

### 调度、统计与扩展题型

- `FsrsScheduler` 使用版本固定的 FSRS v4 参考公式和 0.90 候选目标回忆率，只写入事件的 shadow 字段，不改变当前线上 `MemoryScheduler`。
- `MemoryAnalytics` 从已提交事件重算 7/30 日跨日观察、能力覆盖和练习正确率；没有样本显示未知，不把同日纠错当成长期间隔证据。统计页已展示这些指标。
- `ContentEligibility` 对题型素材做资格检查。审核过的义项和例句才能进入验证级英文产出；旧词库可由用户主动开启基础产出，并以 `legacy-fallback-v1` 记录内容来源。
- 新增英文产出学习流，使用独立 `englishProduction` `LearningItemState`，不会污染识别卡；新增疑难干预策略，按失忆次数给出重学、产出、检查内容或暂停建议。
- `AiExplanationCache` 改为带内容/模板/提供商/模型元数据的有界 LRU 缓存，默认最多 80 项或 1 MiB，缓存键不含凭据，核心学习不依赖 AI。
- AI key 不再写入 SharedPreferences 的配置 JSON；由 `flutter_secure_storage` 保存，旧 key 首次读取时迁移，备份与学习导出不包含凭据。
- 听力与拼写在没有音频/拼写素材时由资格层明确禁用，不会悄悄生成无内容题。

## 验证结果

- `flutter test --no-pub`：全量通过，现有回归与新增测试共 78 项，覆盖资格、FSRS 参考初始向量、能力隔离、观察窗口、AI 缓存、偏好、计划排除和迁移故障注入。
- `flutter build apk --debug --no-pub`：构建成功，产物为 `build/app/outputs/flutter-apk/app-debug.apk`。
- `flutter test integration_test/sqlite_learning_core_test.dart -d <Android device>`：真实 Android 设备通过 SQLite 事务、重复提交幂等、识别/产出能力隔离、重启读取和导入失败回滚。
- 直接 Dart analyzer 通过且无诊断；`flutter analyze --no-pub` 仍会被当前 Flutter 分析服务器的 JSON `FormatException` 中断。
- Android 构建验证了 sqflite、安全凭据插件和新路由可编译；macOS runner 已生成，但当前环境 CocoaPods 无效，macOS 集成测试无法启动。

## 仍需真实设备或内容运营完成的边界

- FSRS shadow 与旧调度器的效果比较需要真实跨日样本；在此之前不自动替换线上调度。
- 旧词库仍是 `legacy-unreviewed` 内容，英文产出默认以基础练习降级；要启用审核级产出，需要补充人工确认的义项、例句和多义项映射。
- 听力和拼写题型保留在 `LearningSkill` 边界内，待音频/拼写素材达到资格后再接入计划器。
- Android 已覆盖事务和导入回滚；杀进程时机、后台恢复和 10 万事件性能仍需在发布候选版本上做长时设备基线，属于持续验证而非未实现代码。
