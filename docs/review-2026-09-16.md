# 快速配对与记忆功能审查

日期：2026-09-16。依据当前工作区实际源码（包含既有未提交修改），不是仅对照旧文档。本次不修改业务代码、不连接或操作手机。

结论：基础配对和记忆事件架构已实现，但还不能按“完整、可靠的学习闭环”验收。主要缺口在保存策略、恢复、主动回忆证据和选项正确性。

## 已实现的能力

| 功能 | 当前实现 | 边界 |
|---|---|---|
| 英文词到中文释义四选一 | 等级/词性干扰项、随机选项、正确性判定 | 多义词兜底仍可出现多个有效答案 |
| 统一反馈节奏 | 正确/错误/超时共用 800ms；按实际时间倒计时 | 逐题检查点重新引入中途序列化和持久化 |
| 会话内纠错 | 错题/超时/慢答重放、题号间隔、冷却、单词及总尝试上限 | 尾部主队列为空会主动缩短间隔以收敛，不能承诺始终隔够 N 个词 |
| 暂停/继续/重置 | 保留剩余时间、重复暂停幂等、取消旧反馈计时器 | 后台暂停又触发了快照保存 |
| 结果区分 | 首答正确率、总作答、纠错成功等 | 达到上限不代表所有词已掌握 |
| 整轮记忆提交 | 队列结束后提交事件、SRS、额度、测试记录；失败可重试 | 整轮多笔写入不是一笔整体事务；逐事件幂等已实现 |
| 到期/疑难/新词计划 | 独立计划器、暂停词排除、新词额度、时间预算 | 当前也选择 extraPractice，不是严格“仅到期”模式 |
| 记忆调度 | 自定义 SRS、难度/稳定度/到期日；区分首答及会话重测、提示 | 并未证明长期学习效果；FSRS 仍仅影子记录 |
| 主动回忆 | 显示答案、自评、独立 meaningRecall 状态 | 当前所有正常自评被归为非独立回忆 |
| 英文产出 | 提示、作答、能力独立状态、素材资格 | 旧内容使用基础练习降级，不等于全面义项审核 |
| 听力/独立拼写 | 能力类型和资格边界 | 缺乏素材时禁用，不能算已交付学习模式 |
| 记忆统计 | 7/30 天观察、能力覆盖、学习历史 | 观察指标跨能力混合，需要修正 |

## 审查发现（按优先级）

### P1：中途不保存的明确要求已被重新破坏

`lib/session/session_controller.dart:454` 在每次结算后调用 `_saveCheckpoint()`；暂停也调用。`lib/session/base_providers.dart` 已给正式控制器装配检查点仓储。该路径通过 `SessionCheckpointStore.save` 把包含完整 attempts、队列、配置的 JSON 写入 SharedPreferences，并非只存内存。即使 Future 不被 await，快照构建和 JSON 编码仍在调用路径上。

最小本地复现：只回答第一题，控制器仍处于 resolved，SharedPreferences 已存在包含一条答案的检查点。现有“中途零 IO”测试使用未装配 checkpointStore 的控制器或只统计 ProgressRepository，因此不能证明正式路径零写入。

建议：按用户已明确的整轮保存策略移除答题/暂停的持久化快照；如另需崩溃恢复，必须先明确与该策略的取舍，不能把异步写入当作“不保存”。

### P1：主动回忆的正常路径无法贡献独立长期回忆

`lib/screens/active_recall_screen.dart:116` 把 `_revealed` 传作 `answerRevealed`；评分按钮仅在 `_revealed=true` 后出现。因而先认真回忆、再展开核对并选择“想起/很轻松”的正常流程也必然成为非独立回忆。

`RecallEvaluator` 因此令 `countsAsLongTermReview=false`；`MemoryScheduler` 按短期强化处理，正向稳定度增长被限制，并排除出独立长期观察指标。不是完全没有保存或完全不更新 SRS，而是证据类别错误。

本地复现：到期词、自评 easy、answerRevealed=true，评估仍返回非长期回忆。建议在揭示前记录用户是否已经回忆成功，将“核对答案”和“依赖答案才答出”区分；继续保留 selfReport 来源。

### P2：检查点写入与恢复没有形成一致闭环

`lib/screens/test_screen.dart:54` 依赖 `settings.hasActiveSession` 才恢复；当前逐题快照不同时写 currentSessionId/remainingWordIds，新会话即使有检查点也可能直接重新开始。

即使通过旧设置进入恢复，`lib/session/session_controller.dart:374` 无视 checkpoint.status，统一恢复成 waiting。答题反馈期保存的快照已经包含当前词的 attempt，却仍把该题重新开放作答；超时快照还可能以 0ms 再次超时。

最小复现：第一题已正确且快照已记录，恢复后同一个词重新成为 waiting，旧 attempt 仍在。建议遵守“不保存中途”的策略消除这条正式路径；若保留旧版本兼容恢复，按快照状态恢复并防止已结算题重复记忆提交。

### P2：干扰项兜底可以把目标词的另一条正确释义放回选项

`lib/domain/distractor.dart:109` 的兜底只检查精确去重，绕过前面的全部释义/包含冲突检查。前面的补充函数还将“还需要几个”和“总共已有几个”比较，可能过早停止，让兜底更常触发。

最小复现：目标词释义为“银行、岸”，同级候选“猫”、其他级别候选“岸、狗”，最终选项同时含“银行”和“岸”，但 correctIndex 只认可“银行”。选择真实有效释义会被记录成错误并影响重放和 SRS。

建议所有补充路径共用冲突判断；不足时扩大安全候选范围或明确降级，不能重新引入已排除释义。

### P2：7/30 天观察把不同能力当成同一个项目

`lib/features/progress/domain/memory_analytics.dart:64-67` 仅按 wordId 分组，没有包含 skill/learningItemId。代码路径允许第 0 天的识别和第 7 天的英文产出组成一个长期观察样本，即便产出是首次测量该能力。

此项为静态确认的数据分组问题，未新增设备实验。建议按稳定词条+能力（更优先使用 learningItemId）计算观察窗口，再按产品需求汇总。
